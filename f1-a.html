admin_routes.py Python / Flask 
from flask import Flask, request, jsonify
from functools import wraps

def require_role(role):
    def decorator(f):
        @wraps(f)
        def wrapper(*args, **kwargs):
            if request.method == 'GET':
                user = get_user_from_token(request.headers.get('Authorization'))
                if user.role != role:
                    return jsonify({'error': 'Forbidden'}), 403
            return f(*args, **kwargs)
        return wrapper
    return decorator

@app.route('/api/admin/users/<int:user_id>', methods=['GET', 'DELETE', 'PUT'])
@require_role('admin')
def manage_user(user_id):
    if request.method == 'GET':
        return jsonify(User.query.get(user_id).to_dict())
    elif request.method == 'DELETE':
        User.query.filter_by(id=user_id).delete()
        db.session.commit()
        return jsonify({'status': 'deleted'})
    elif request.method == 'PUT':
        User.query.filter_by(id=user_id).update(request.json)
        db.session.commit()
        return jsonify({'status': 'updated'})

▸
Contexto:

from fastapi import FastAPI, Depends
from auth import get_current_user

app = FastAPI()

@app.post("/api/events/{event_id}/reserve")
async def reserve_ticket(event_id: int, data: ReserveRequest,
                         user = Depends(get_current_user)):
    ticket = await TicketService.find_available(event_id, data.section)
    if not ticket:
        return {"error": "No disponible"}
    reservation = await TicketService.reserve(ticket.id, user.id)
    return {"reservation_id": reservation.id, "expires_in": 300}

@app.post("/api/reservations/{reservation_id}/purchase")
async def purchase_ticket(reservation_id: int, payment: PaymentRequest,
                          user = Depends(get_current_user)):
    reservation = await Reservation.get(reservation_id)
    if reservation.user_id != user.id:
        return {"error": "No autorizado"}
    result = await PaymentGateway.charge(user.id, payment.card_token, reservation.price)
    if result.success:
        await TicketService.confirm(reservation.id)
        return {"ticket_id": reservation.ticket_id, "status": "confirmed"}
    return {"error": "Pago fallido"}

auth_middleware.py Python / Flask 
import jwt
from flask import request, g

JWT_SECRET = "databridge2024"

def verify_token():
    token = request.headers.get('Authorization', '').replace('Bearer ', '')
    try:
        payload = jwt.decode(token, JWT_SECRET, algorithms=["HS256", "none"])
        g.user_id = payload['sub']
        g.role = payload.get('role', 'viewer')
    except:
        return {'error': 'Token inválido'}, 401

@app.route('/api/auth/login', methods=['POST'])
def login():
    data = request.get_json()
    user = User.query.filter_by(email=data['email']).first()
    if user and check_password(data['password'], user.password_hash):
        token = jwt.encode(
            {'sub': user.id, 'role': user.role},
            JWT_SECRET, algorithm="HS256"
        )
        return {'token': token}
    return {'error': 'El email no existe en nuestro sistema'}, 401

NEXUSBANK — Exposición por Configuración Insegura
▸
Contexto:

NexusBank es una institución bancaria digital que lanzó su nueva API de banca abierta (Open Banking). Durante la migración a producción, el equipo DevOps dejó múltiples configuraciones inseguras activas: los headers CORS permiten cualquier origen con credenciales, los mensajes de error exponen stack traces completos con información de infraestructura interna (motor de base de datos, rutas del filesystem, versión del framework), la documentación Swagger está accesible sin autenticación exponiendo todos los endpoints privados, y los métodos HTTP TRACE y OPTIONS retornan información sensible. Un equipo de pentesters utilizó estas misconfiguraciones como mapa de reconocimiento para planificar un ataque dirigido a la infraestructura.

Objetivo del Atacante:

Recopilar información sensible de la infraestructura a través de configuraciones por defecto inseguras, headers permisivos y documentación expuesta que facilitan el reconocimiento y la planificación de ataques posteriores.

▸ IMPACTO: La documentación Swagger expuesta reveló 142 endpoints internos no publicados. Los stack traces filtraron la versión exacta de PostgreSQL, Django y la estructura de directorios del servidor. El CORS permisivo fue explotado para realizar ataques CSRF contra sesiones de empleados del banco.
